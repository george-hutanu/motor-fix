## Scenarios the specs prove (from spec.md)

| Scenario | Seed | Expect |
| --- | --- | --- |
| SC-001 order and counts | 6 approved garages: 3 `works_on` BMW, 2 `does_not_take`, 1 no row; 1 suspended `works_on` | items: the 3 takers first (`stance: works_on`), then 3 with `does_not_take`/`unstated`; the suspended one absent; `counts {3, 3}`, `total 6` |
| SC-002 paging never mixes | 48 approved, 30 takers | page 1: 20 takers; page 2: 10 takers then 10 others; page 3: 8 others, `nextCursor: null`; every page `counts {30, 18}`; no id repeated or missing |
| SC-003 order inside a group | takers "Auto Delta", "Auto Alfa", "Auto Beta"; two takers with one name; a refuser named "AAA" | Alfa, Beta, Delta; same-name pair by id across a page boundary; "AAA" after the last taker |
| SC-004 public | no `Authorization` | 200, not `sign_in_required` |
| SC-005 nobody takes it | 5 approved, none `works_on` Tesla | 5 items all in group B, `counts {0, 5}`; with no approved garage `counts {0, 0}`, `items []` |
| FR-009 refusals | `brandId=abc`; unknown uuid; `cursor=…` from another brand or garbage | 400 `validation_failed`; 404 `not_found`; 400 `invalid_cursor` |

## Try it against a running API

```sh
sh scripts/heavy.sh npx nx run api:build > /tmp/st43-build.log 2>&1; echo "exit $?"
DATABASE_URL=$DATABASE_URL REDIS_URL=$REDIS_URL AUTH_TOKEN_SECRET=dev node dist/apps/api/main.js &   # a dev server holds no heavy slot
BRAND=$(psql "$DATABASE_URL" -Atc "select id from brand where slug='bmw'")
curl -s "http://localhost:3000/api/v1/search/garages?brandId=$BRAND" | jq '{counts, total, next: .nextCursor, first: .items[0]}'
curl -s "http://localhost:3000/api/v1/search/garages?brandId=$BRAND&cursor=$(curl -s "http://localhost:3000/api/v1/search/garages?brandId=$BRAND" | jq -r .nextCursor)" | jq '.items | map(.stance)'
```

Expected: `works_on` items before any `does_not_take`/`unstated` one; the second page continues the group.
