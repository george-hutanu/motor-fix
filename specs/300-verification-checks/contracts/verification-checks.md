# Contracts: ST-300 verification checks

## Route

`PUT /api/v1/admin/verification-files/{id}/checks/{kind}` — `VerificationChecksController` in `libs/domain/src/garages/verification-checks.controller.ts`, `@ApiTags('admin')`, `@ApiBearerAuth()`, `@Requires('admin.garages')` (Swagger decorators as `admin-overview.controller.ts`). Idempotent in the HTTP sense: the same body twice leaves the same row (and writes two audit entries).

Path: `id` the file's uuid (a malformed or unknown id is 404, as the file service answers); `kind` one of the 8 kinds (anything else is 422).

Request body, `RecordVerificationCheckDto` (`libs/contracts/src/verification-checks.ts`, class-validator as `staff-invite.dto.ts`):

| Field | Type | Rule |
| --- | --- | --- |
| `result` | `'ok' \| 'warning' \| 'failed'` | required (`@IsIn`); `not_run` is never written back |
| `detail` | string | optional; trimmed; 1–200 characters (`@Length`), no control characters; required by the service when `result` is `warning` or `failed` |
| `activities` | string[] | optional; each a `rar_activity.code`; required (may be `[]`) when `kind = activities` and `result = ok`; refused with 400 on any other kind |

Answers:

| Status | `code` | When |
| --- | --- | --- |
| 200 | — | `VerificationCheckRecordedDto` below |
| 400 | `validation_failed` | a malformed body (the global `ValidationPipe`); a missing detail on `warning`/`failed`; a detail over 200; an unknown activity code; `activities` on another kind or missing on `activities = ok` (`errors: [{ field, code }]`) |
| 404 | `not_found` | not an admin; unknown or malformed file id |
| 409 | `verification_file_decided` | the file is `approved`, `rejected` or `more_requested`; message "Dosarul e deja decis" |
| 422 | `verification_check_kind_unknown` | `kind` not one of the 8 |

Response, `VerificationCheckRecordedDto`:

```json
{
  "check": {
    "id": "uuid", "fileId": "uuid", "kind": "rar", "automatic": false,
    "result": "ok", "detail": "Autorizație găsită în registru, aceeași firmă și adresă",
    "recordedBy": "uuid", "recordedAt": "2026-10-07T12:00:00.000Z"
  },
  "summary": { "ro": "Autorizație RAR verificată", "en": "RAR licence checked" },
  "rarActivities": ["mechanics", "brakes"]
}
```

`check` is `VerificationCheckDto` (every column; `detail`, `recordedBy`, `recordedAt` nullable), `summary` the file's new line in both languages, `rarActivities` the garage's list after the save (always present, so the activities form needs no second read).

## Use case

`VerificationChecksService.record(tx, actor, fileId, kind, body): Promise<VerificationCheckRecordedDto>` (`libs/domain/src/garages/verification-checks.service.ts`), called by the controller inside `prisma.$transaction`, and by the three form stories' server code. Order: admin check → file read (404) → status check (409) → kind check (422) → body rules (400) → activities codes against `rar_activity` (400) → read the check `FOR UPDATE` (so the audit's old values are the last committed save's) → `update` the check (`result`, `detail`, `recordedBy`, `recordedAt`) → garage `update` for `activities` with a list → one `AuditPort.record` → one `EventPort.record` → read the 8 checks and build the summary.

`VerificationService.submit()` / `resend()`: unchanged signatures; after the file row, `createMany` of the 8 `not_run` rows with `skipDuplicates`, before the event.

## Pure functions (`libs/contracts/src/verification-checks.ts`, exported from `index.ts`)

```ts
export const VERIFICATION_CHECK_KINDS = ['company', 'caen', 'rar', 'activities', 'representative', 'address', 'photos', 'documents'] as const;
export const VERIFICATION_CHECK_RESULTS = ['not_run', 'ok', 'warning', 'failed'] as const;
export type VerificationCheckKind = …; export type VerificationCheckResult = …;
export type Lamp = 'green' | 'amber' | 'red' | 'grey';
export function lamp(result: VerificationCheckResult): Lamp;
export function checkSummary(
  checks: readonly { kind: VerificationCheckKind; result: VerificationCheckResult; detail: string | null }[],
  language: 'ro' | 'en',
): string;
```

`checkSummary` examples (spec SC-003 and Clarifications): `company=ok, rar=ok` → "CUI și autorizație RAR verificate"; `rar=failed` → "Lipsește autorizația RAR"; `company=ok, photos=warning "neclare"` → "CUI verificat · fotografii neclare"; nothing → "Neverificat"; `rar=ok` alone → "Autorizație RAR verificată"; English: "Company ID checked", "RAR licence checked", "Company ID and RAR licence checked", "RAR licence missing", "Not checked", and `photos neclare` → "photos neclare" (the detail stays as typed). A missing kind in the input counts as `not_run`.
